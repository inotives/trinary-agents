# Feature dashboard reference

The optional `dashboard.html` is a read-only snapshot of one feature's task
graph, generated by `scripts/generate_dashboard.py`. The workflow in
[`SKILL.md`](../SKILL.md) must work without it. This file describes what the
generator produces; agents running the workflow only need the generation rules
in `SKILL.md`.

## Requirements

Generation requires Python 3 and uses only the standard library; no packages
need to be installed. Check availability with `python3 --version`. If
`python3` is unavailable on macOS, direct the human to install Python 3 using
the [official macOS installer](https://www.python.org/downloads/macos/), open a
new terminal, and verify with `python3 --version`. Do not modify or remove
Apple's system Python.

The DaisyUI 5.7.50 stylesheet in `assets/dashboard/` is embedded into each
generated page with its license notice. Rendering uses browser-native DOM and
SVG APIs; the page makes no third-party runtime requests.

## Inputs and validation

- Project display name: `Project name: <name>` in `trinary-workspace/README.md`.
- Feature ID and title: the feature README frontmatter.
- Tasks: every `tasks/T-*/README.md` frontmatter (`id`, `title`, `status`,
  `depends_on`). Generation fails on missing fields, duplicate IDs, unknown
  dependencies, dependency cycles, or a status not listed in the SKILL.md
  status table.
- Activity: timestamped handoff files in each task's `handoffs/` folder. The
  latest handoff per task supplies its activity and recipient. Noncanonical
  filenames produce a warning.

An existing `dashboard.html` without the generator's marker comment is never
overwritten or removed. A feature with no valid tasks has no dashboard.

## Layout

- Title `Trinary-AGENTs Flow :: <Project Name>` and subtitle
  `IP-XXXX--<feature title> workflow viewer`.
- Overview: a left-to-right dependency map with arrows from prerequisites to
  dependent tasks, alongside completion progress. Compact nodes show the task
  ID and a status symbol, explained by a legend. An accessible text equivalent
  exposes full task IDs, titles, statuses, and prerequisites. The map scrolls
  within its panel when wider than the available space.
- Task board with four lanes:

  | Lane | Statuses |
  | --- | --- |
  | Project manager | `queued`, `ready`, `blocked` |
  | Worker | `in_progress`, `changes_requested` |
  | Reviewer | `review` |
  | Done | `done` |

  Cards show task ID/title, status, current owner, dependencies, cycle time,
  and the latest handoff role/outcome/time with its summary when present.
- Handoff timeline: every timestamped handoff, newest first, with its task,
  role, recipient, outcome, and summary when present. Selecting one opens its
  source as plain text.
- Lanes and the timeline scroll within their panels when content overflows.

## Current owner

Owner is `Completed` for `done` and always `Human` for `blocked`, regardless of
handoff recipient. Otherwise it is the latest handoff's recipient when usable,
falling back to `Reviewer` for `review`, `Worker` for `in_progress`, and
`Project manager` for other statuses.

## Task cycle time

Cycle time is wall-clock time from the earliest project-manager handoff
addressed to a worker through the latest approved reviewer handoff for
completed tasks; it includes review rounds and human waits. Unfinished
dispatched tasks are measured through generation time and marked `(ongoing)`.
`Total task cycle time` below completion progress sums the available
durations. Missing timestamps are not estimated: tasks show `Not started` when
no worker dispatch exists and `Time unavailable` when a required timestamp is
missing or invalid. This metric is not active effort or total feature duration.

## Auto-refresh

The auto-refresh toggle is off by default, with an adjustable 5–60 second
interval in five-second steps, defaulting to 10 seconds. The interval persists
in a URL query parameter while the `#auto-refresh` hash controls on/off state,
which also works for `file://` dashboards without session storage. Changing the
interval while refresh is enabled restarts its timer. The enabled toggle turns
green and animates its icon unless `prefers-reduced-motion` is set.
